# Picasa 式翻图与封面预览栏：实施规划

状态：功能已实施，纳入 v0.4.0 完整离线预发布版；窗口截图检查因接口超时尚未完成。用户已确认“当前图片最清晰，越远越透明”。下文保留分阶段实施记录，其中“不发布”描述的是当时的本地试用交付；当前发布范围见 [v0.4.0 更新说明](RELEASE-v0.4.0.md)。

## 目标与范围

在现有 Rust / egui 单图查看界面中增加顺手的方向键翻图和底部封面浏览。继续复用当前图片解码、压缩包密码、RAW、GIF/WebP 动画及缩放逻辑，不新增依赖。

| 操作 | 单图查看中的新默认行为 |
|---|---|
| 左 / 右方向键 | 上一张 / 下一张；首尾停住，不重新加载当前图片 |
| 上 / 下方向键 | 平滑放大 / 缩小，复用当前目标倍率和插值机制 |
| 点击底部封面 | 进入对应图片，沿用未保存编辑确认流程 |

管理界面保留网格方向键导航；输入框、密码框、菜单和独立对话框优先处理自身按键。比较和编辑工作区保留原有上下文。Ctrl+方向键、PageUp/PageDown、空格、退格、数字键盘和鼠标滚轮继续可用；已有自定义快捷键优先。

## 底部视觉与交互

- 单图查看且当前浏览序列有多张图片时，底部显示封面式预览栏；文件夹和 ZIP/RAR/7z 使用同一套呈现。
- 当前封面居中、最大、完全清晰；两侧依距离逐渐缩小、变透明，采用重叠的封面卡片与轻微透视感，原始图片保持比例。
- 切换图片时，封面位置、尺寸和透明度做短时平滑过渡；不采用加载整套图片的动画实现。
- 显示 `1/84` 形式的序号及当前文件名。序号与实际翻图序列一致：遵循当前排序、筛选及多选批次，只计图片。
- 窗口较小时减少可见封面，不横向撑大窗口；单张图片不额外占用预览栏高度。
- 缩略图未准备好时显示占位卡片，失败不反复重试、不弹后台密码框、不影响主图；点击后由正常看图流程处理错误或密码。

## 内存、响应与职责

1. 新增独立的 `coverflow` 界面模块；沿用 egui 现有绘图、纹理和时间插值能力。
2. 绘制和请求局限在当前图片附近，最多约 11 张；缩略纹理最多 32 张、单张不超过 128×128，约 2 MiB RGBA 预算，按 LRU 淘汰。
3. 独立单任务缩略图队列避免打断 GIF/WebP 动画。后台缩略图工作进程树限 512 MiB、30 秒；主图解码保留原有 2 GiB 限额。它们是分项预算，不是整个应用的总内存上限。
4. 主图读取优先。连续翻图、切目录、重读压缩包或退出时取消过期缩略任务；旧来源的结果不写入新图库。后台任务复用当前会话密码，不持久化密码。
5. 浏览顺序只在排序、筛选、多选或来源变化时重新生成；稳定帧不复制或遍历整个图库。管理缩略图和原有全图缓存不在本次顺便重构。

## 实施步骤与验收

1. **方向键与输入上下文** → 验证 egui 与 Win32 原生键盘路径一致、长按有效，管理/输入/对话框及旧修饰键不被抢占。
2. **封面栏与有界缩略图** → 验证首尾、点击、批次序号、排序筛选、快速切换与动画共存；大图库稳定帧只处理可见小窗口，缓存不超预算，旧结果被丢弃。
3. **构建与可运行试用包** → 运行有针对性的回归及现有测试；检查真实界面与小窗口表现，重新核验图片/压缩包和动画读取，提供本地完整离线试用目录。

本轮先交付本地可试用版本和操作说明。保留现有离线版及其用户数据；不自动关闭用户窗口，不改文件关联，也不自动替换已经发布的 GitHub Release。

## 试用反馈修订：连续显示与动画

用户反馈第一版封面动画生硬，快速翻图时会出现欢迎页。本次修订将其作为两项可验证的缺陷处理：

1. 封面运动保存位置和速度，使用随真实帧时间计算的临界阻尼过渡；尺寸、透视和透明度使用连续曲线，边缘淡出。远跳时做 240ms 交接，最多两组各 13 张，不随连跳累积。
2. 数据读取与画面保留分离。开始读取仍释放当前像素引用，但显示层保留最多 64×64 的上一帧马赛克；目标低清数据可用时替换为目标预览，高清就绪后才画高清。`ready` 回调不清除保留帧，避免 B 已读完未绘制又跳 C 的同帧竞态。
3. 缩略结果补充原尺寸以固定比例；已解码缓存可直接生成低清数据，不再重新读取。慢任务超过 150ms 时仅补当前目标预览，维持单后台任务和 512 MiB 限额。
4. 每帧清背景且只绘制一个显示阶段，避免透明新图露出旧图。读取期不从旧 workspace 套用打印参数；预览期删除需回管理模式或等图像就绪。

本次 **187 项单测通过，2 项默认跳过**，包括帧率一致性、连续反向/停稳、高索引精度、大跳转有界交接、旧帧保留、目标/来源隔离、透明替换，以及实际 `draw_image` 快速导航不显示欢迎页的回归。修订后的离线包再次通过 **82 项真实进程回归**（25 静态／压缩包、24 动画、19 RAW／高位／元数据、14 缩略图）；缩略图回归同时检查用于精确比例的原尺寸字段。真实窗口视觉检查仍受捕获接口限制。

## 主力看图试用修订：平直底栏、PSD 和系统关联

2026-11-11，用户进一步明确以自己的主力看图软件为目标。此次范围为三项具体实现及独立调研：

1. 底栏去掉倾斜、透视网格和叠压，改平直矩形胶片带，保留照片比例、间距、选中突出、连续阻尼运动和有界跨区交接；不修改低清接力、来源隔离、任务取消和 LRU 接口。验证真实 egui 输出几何、不同帧率、窄窗、点击间隙与布局。
2. 复用现有原生引擎读取 PSD/PSB 合成图；探测、编辑恢复和导出固定首图，图层不能成为动画或 TIFF 式翻页。以自产 RGB/RLE/RGBA/16bit/CMYK/ICC/图层样本验证像素，保留输入、RGBA 和进程预算。禁止覆写 PSD/PSB 内容及属性，本地目录评级和显式文件管理继续可用。
3. 离线包与引导包均附 Setup/Remove 文件关联入口。当前用户注册图片候选格式和三个压缩包右键；图片默认应用交 Windows 确认，ZIP/RAR/7z 不列入批量图片默认清单。隔离注册表测试覆盖 54 种图片、3 个右键、重复安装／卸载、特殊路径、多个便携位置所有权和其他软件保护。
4. [GitHub 调研与后续取舍](RUST-VIEWER-COMPARISON.md) 根据项目官方 README／清单分别核查实现、目标、维护状态与许可；只提出适合日常主力使用的后续建议，本轮不新增那些建议功能。

最终单元回归 **192 通过、2 跳过**。打包后的 x64 离线 EXE 在只保留 Windows 系统 PATH 时通过 **103 项真实进程回归**：25 静态／压缩包、24 动画、19 RAW／高位／元数据、14 缩略图、21 PSD/PSB。后者含 ZIP 列举、加密 7z、缩略图和单张合成导出；测试源文件未变。Windows PowerShell 5.1 的隔离注册／卸载测试也通过；未对用户安装真实关联。

窗口可启动并被工具枚举，但新构建两次实际捕获均返回 `window capture timed out: timed out waiting on channel`，未完成真实窗口视觉验收。几何／点击回归不能替代主观动画观感或长期大图库压力测试。保持本地试用交付，不覆盖已发布 v0.3.0 Release。

## 大 PSD 文件误拦修复

用户反馈超过512 MiB的PSD都提示文件不存在或读取超限。实际样本约1.98 GiB，保存的合成画布仅900×1200（RGBA约4.1 MiB），故根因是源文件大小与解码像素预算混用，而非已经证实的内存耗尽。

最小修复：本地PSD/PSB按独立64 GiB源文件门槛检查；大源还需有效8BPS签名和版本。原生路径直接按绝对路径定位合成scene[0]，跳过图层，不复制整个源文件。普通输入、压缩包提取、元数据和像素/进程资源限额不作全局放宽；不引入降采样或改变Pixels尺寸语义。Page快捷键同步修正其输入门，Render/处理记录恢复复用受保护的源访问路径。不存在的文件与超限错误分别报告。

验证：新增大图层块PSD/PSB、中文及特殊字符路径、完整像素和16位输出、伪装扩展名、普通格式保留512 MiB、多页单图、像素超限与缺失文件回归。全量198项通过、2项跳过；完整离线包的103项静态/压缩包/动画/RAW/缩略/PSD进程回归通过。实际私人PSD的8条进程流程均成功，主图仍完整900×1200，打开约1.3秒；进程树私有提交内存100ms采样约40 MiB。源文件大小、修改时间与分段指纹不变；样本不公开或打包。

旧试用程序正在运行，因此交付到独立的“RustView-大PSD修复版”，以SQLite只读备份API复制一致目录库，保留现有窗口。仍是本地试用更新。

## ZIP／RAR／7z 内大 PSD 自动读取

用户明确要求包内超过512 MiB的PSD直接看，不先手动解压。实现复用随附7-Zip，只把选中PSD/PSB流式写入每个任务独占的临时文件，再读取保存的合成图；本地和包内源文件上限统一64 GiB，不放宽RGBA或工作进程内存预算。

大条目先检查索引大小与临时盘余量，传输缓冲64 KiB，开头检查Photoshop签名/版本，实际解出长度严格核对；每16 MiB复查磁盘空间并保留2 GiB。只在大PSD路径启用这些磁盘规则，普通图片与文件管理沿用既有提取行为。错误停止并回收解压进程，取消/超时先终止整个工作进程树；进程和Job句柄释放后清理临时目录，Windows暂时占用时有限重试，清理失败明确报告。

大包内PSD不做胶片带重复提取；管理缩略图只读取当前选中的大PSD，点击任意大PSD仍可前台打开。已有缓存、低清接力、快捷键、GIF/WebP动画和平滑缩放保持。

验证：204项单元测试通过、2项跳过；新增35项真实进程回归使用546,000,130字节自产PSD，覆盖ZIP、RAR5 stored、7z、AES ZIP/7z的列举/主图/缩略/单页/PNG16导出、密码和清理。两项真实取消在写入部分数据后结束，临时目录为空。测试发现并修复AES ZIP缺密码时EOF被误报为数据不完整的问题：EOF等待自然退出并保留7-Zip密码分类，资源错误仍及时停止生产者。RAR密码测试使用原有小型上游夹具，大型加密RAR未实测。生成器和来源进入源码，大档案仅保存在忽略的test-output中。

最终同一x64离线EXE也通过既有103项真实进程回归（25静态/压缩包、24动画、19 RAW/高位/元数据、14缩略、21 PSD），共138项真实流程。交付继续更新原“RustView-大PSD修复版”目录，先备份被替换文件，保持RustView-data不变；本轮不发布GitHub Release。

## 大型加密RAR、快速翻图与退出补测

使用官方签名有效的RAR 7.23评估CLI，仅在忽略目录生成自产测试夹具，不安装、不把RAR创建工具加入看图依赖。两类加密分别为文件数据加密和文件名/数据加密；每张PSD546,589,948字节、合成图512×384、A/B颜色不同。另用m0生成物理体积546,590,398和546,590,638字节的密文包，将“条目解出后大”和“容器本身大”分开验证。

最终关窗修正版通过76项真实进程读取/密码/导出/重复取消测试；390条观测PID记录都确认退出，各请求私有TEMP为空，所有测试源和包的SHA不变。16次严格真实取消通过，结束耗时0.234–0.437秒；8次早取消观察到50.3–122.7 MB部分输入。特定小画布样本的读取进程树私有提交采样最高约19.68 MiB，不包含实际GUI/GPU、Python或系统文件缓存，不能代表整个软件总内存上限。

新增同一Viewer的真实导航probe，复用正常构造状态、导航动作、队列/poll/draw和受控工作进程。8项按10ms/250ms连续切换，核对最终像素、旧generation退休、seed后欢迎页为0、缓存预算与提取中途关窗。压缩型档案在两个大PSD之间切换，物理存储型在大PSD和seed之间切换；所有观测子进程退出、临时目录空。probe不创建原生窗口/封面后台任务，另用原生窗口UIA验证密码重试、键盘切换与退出，不冒充截图验收。

关窗原先只发取消标志后即销毁Viewer，可能让持有临时文件的线程来不及收尾。本次退出先取消并等待主读取、动画和封面任务退休，不派发新任务，保持写操作及未保存编辑保护。真实窗口补测还发现同帧Close/CancelClose会导致退出循环，已改为忙时只CancelClose、结束时只Close；单测和probe增加下一帧原生Close事件反馈，原生窗口也确认可真正退出。当前全量208项单测通过、2项跳过。仍更新本地完整离线试用包，不发布新Release，不分发私人文件、生成大包或RAR评估程序。
